Thermochimica + MOOSE

Hour 2 of the SaltFoss training. Hour 1 computed equilibrium speciation, redox, and off-gassing at single points. This hour makes those same quantities spatial fields inside a MOOSE model, shows what it costs to make that affordable, and previews the pending interface redesign.

Every number in this deck comes from a calculation run on a stated input file in inputs/training/saltfoss_moose/.

Segment 1 · 0:00–0:08

Why spatial

  • Hour 1 closed with: "This is equilibrium only. Rates, transport, and coupling to a reactor model come next hour with MOOSE." This hour delivers that.
  • Thermochimica lives inside MOOSE's chemical_reactions module — there is no dedicated Thermochimica module.
  • [ChemicalComposition] is an Action: it creates scalar AuxVariables and one ThermochimicaData UserObject that solves an independent equilibrium at every selected node or element.
  • Usually no finite-element system is involved — [Problem] solve = false is the normal pattern, unless something couples to the output (Segment 6).
Segment 1 · Real-world case

Depletion-driven thermochemistry

The Virtual Test Bed's one Thermochimica model: msr/msfr/thermochemistry/thermo.i, a Molten Salt Fast Reactor. Griffin depletion and Pronghorn thermal-hydraulics feed a spatially-resolved Thermochimica solve at every mesh node.

Documented result

As the fuel salt depletes without chemistry control, the fluorine potential rises — and iodine volatility increases by at least four orders of magnitude.

Directly relevant to off-gas system design: a redox drift you cannot see in a single-point calculation becomes visible, and quantifiable, as a spatial field.

Segment 2 · 0:08–0:20

Current interface anatomy

! 10_current_syntax.i
[GlobalParams]
  elements = 'Mo Ru'
  output_phases = 'BCCN HCPN'
  output_element_potentials = 'mu:Mo mu:Ru'
[]

[ChemicalComposition]
  [thermo]
    thermofile = NobleMetals-Kaye.dat
    tunit = K
    punit = atm
    munit = moles
    temperature = 2250
  []
[]

Four load-bearing pieces

  • [GlobalParams] carries the flat output_* selectors.
  • thermofile/tunit/punit/munit name the database and units.
  • Variable names encode the selector: mu:Mo, BCCN:Mo, vp:gas_ideal:Mo.
  • solve = false + Steady: Thermochimica is the only physics.

Segment 3 · Limitation to state out loud

The current interface cannot split U(III)/U(IV)

  • output_species only resolves a plain species name.
  • MSFL's U(III)/U(IV) forms — U[3+], U[CN=VI], U[CN=VII], U[Dimer] — are MQMQA cation constituents, not species.
  • There is no flat output parameter that reaches a sublattice constituent. mu:F is the best redox proxy available on this interface.

Fixed in the redesign

The ConstituentFractions typed output (Segment 7) reads the oxidation-state split directly. This is new capability, not just new syntax.

Segment 5 · 0:44–0:54

Making it affordable

41 independent equilibrium solves, same redox sweep as Segment 3, on the current interface's reinitialization_type — the per-node analog of Hour 1's reinit = .TRUE..

ModeWall time
reinitialization_type = none — every node from scratch9.1 s
reinitialization_type = nodal — warm-started5.6 s

State out loud: this is the current interface's single reinit enum. The redesign replaces it with a forked-worker + shared-memory model — batch_size, three warm_start modes, report_performance counters, real thread/MPI parallelism. A materially larger speedup than shown here.

Segment 6 · 0:54–1:05 · Hands-on 2

Coupling out

The other half of Hour 1's hand-off: turning a redox/corrosion quantity into a boundary condition for a coupled model. Segment 3's mu:F profile drives a toy "corrosion marker" diffusion field — a real [Variables] field solved with Newton.

! 14_coupled_bc.i
[BCs]
  [right]
    type = CoupledVarNeumannBC
    variable = marker
    boundary = right
    v = 'mu:F'
    coef = 1e-6
  []
[]

Solve Converged! · marker_right = −0.4526

A real model would couple the Cr dissolution rate from Hour 1 (spanning ~9 orders of magnitude with redox) through this same mechanism.
